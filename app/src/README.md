# Архитектура frontend — состояние после FE-033–FE-037

- `main.tsx` — точка входа React и BrowserRouter.
- `app/` — композиция приложения, маршруты и состояние верхнего уровня.
- `pages/` — Home, Help Select, Catalog, Detail, Added и My Plan; прежние legacy-экраны сохранены отдельно и не подключены к маршрутам.
- `components/common/` — общие элементы форм.
- `components/layout/` — общий каркас и навигация.
- `components/activities/` — переиспользуемые элементы текущих карточек.
- `data/catalog/` — нормализованный каталог регулярных групп и справочники. Старый `data/activities.json` сохранён, но не используется новым каталогом.
- `types/domain.ts` — восемь сущностей Development Baseline v1.15 и перечисления.
- `types/index.ts` — публичные экспорты новой доменной модели.
- `types/legacy.ts` — временные типы существующего каталога и анкеты.
- `utils/business/legacyModel.ts` — прежние правила, отделённые от React UI.
- `storage/` — типизированное чтение и сохранение локального состояния.
- `styles/` — существующие стили без изменения оформления.

Все исполняемые модули приложения используют TS/TSX. Проверка `npm run
typecheck` охватывает `src` и конфигурацию Vite; `npm run build` сначала
проверяет типы. `allowJs` выключен, `strict` включён. ESLint проверяет TS/TSX.

## Граница миграции

Новый `ActivityPlan` содержит `activityIds: string[]` без верхнего лимита.
Уникальность ID, ссылочная целостность, корректность Schedule и числовых
значений проверяются runtime-нормализацией FE-006; интерфейсы TypeScript
не выполняют эти проверки при загрузке JSON.

`ActivityGroup` требует `venueId` для offline/hybrid и допускает отсутствие
или null для online. Доступность площадки допускает неизвестное значение
null. Для полей, перечисления которых не определены baseline (например,
`Organizer.type`, `verificationStatus`, `skillLevel`), не введены вымышленные
закрытые наборы значений. Техническое представление weekday — ISO 1–7.

Новые регулярные группы подключены к Catalog через normalize → filter → order
→ render. Добавления в план из Catalog нет. Detail показывает практическую
информацию и добавляет уникальный ID группы без лимита и toggle-удаления.
Added подтверждает только совпавший контекст реального недавнего добавления;
прямой URL и reload без runtime-контекста дают нейтральное состояние.
My Plan показывает число групп, месячную стоимость, общий бюджет, список
занятий, вертикальное недельное расписание и неблокирующие предупреждения.
App использует полный контракт ActivityPlan. Бюджет един для плана и фильтра
Catalog. SelectionPreferences существует только в памяти и после применения
становится обычными фильтрами; после reload восстанавливается только бюджет.

Существующие legacy-модули с числовыми ID и прежними правилами сохранены,
но не смешиваются с регулярными группами. /preferences и /route больше не
зарегистрированы и не представлены в навигации. Старые ключи localStorage
не читаются и не перезаписываются новым сценарием. Новый ключ
`dolgoletie.activityPlan.v1` хранит только пять полей контракта ActivityPlan.
Правила сохранения и восстановления описаны в `storage/README.md`.
aggregatePlan пересчитывает сессии, стоимость и предупреждения после изменения
выбора или бюджета. Удаление не требует подтверждения; Undo восстанавливает
только последнее удаление в текущем сеансе и не записывается в localStorage.

FE-023/024: Catalog дополнен локальным поиском и условиями по существующим
skillLevel/physicalLoad/elevator/stepFreeEntrance. Они применяются через AND
в том же pipeline, не меняют порядок, стоимость или выбранные группы.
Все новые параметры временные и после reload сбрасываются. Help Select
сохраняет ровно пять утверждённых параметров; фильтр enrollmentStatus не добавлен.
Семантика поиска и unknown-доступности описана в `utils/business/README.md`.

FE-033–037: русские lang/title, mobile-first layout, нативные подписи полей,
skip link и RouteFocus для SPA-переходов. Каталог и My Plan восстанавливают
focus после исчезающих действий. Бизнес-функции и storage-контракт не менялись.
Матрица ширин, клавиатурная проверка и ограничения accessibility-аудита
описаны в `../UI_REVIEW_FE033_037.md`.
