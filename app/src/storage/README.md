# ActivityPlan: локальное сохранение — FE-032

Единственный новый ключ: `dolgoletie.activityPlan.v1`.

Значение — JSON-объект контракта `ActivityPlan`, ровно пять полей:

```json
{
  "activityIds": ["group-walk"],
  "monthlyBudget": 5000,
  "estimatedMonthlyTotal": 4000,
  "createdAt": "2026-10-26T10:00:00.000Z",
  "updatedAt": "2026-10-26T11:00:00.000Z"
}
```

Сумма — пересчитываемый кеш, а не доверенный источник. Нормализатор плана
использует актуальный нормализованный каталог и `aggregatePlan`. Сохраняются
уникальные существующие строковые ID без лимита количества. Неизвестные ID,
числа и дубликаты отбрасываются без потери остальных валидных групп.

Бюджет допускает 0, 2000, 5000, 10000 или null. Остальные значения
восстанавливаются как null независимо от выбранных групп. Неверный корневой
объект или activityIds не-массив дают пустой план; повреждённый JSON тоже не
роняет приложение. Отсутствующие/некорректные timestamps заменяются текущим
временем или валидной датой создания; updatedAt не предшествует createdAt
после восстановления. Время для чистой нормализации передаётся явно.

`loadActivityPlan` читает только новый ключ. Старые `myPlan` и
`parentPreferences` не мигрируются, не читаются и не перезаписываются.
Новый сценарий не смешивает разовые legacy-события с регулярными группами.

`saveActivityPlan` формирует объект заново, поэтому дополнительные поля
не попадают в JSON. SelectionPreferences, Catalog filters кроме бюджета,
контекст Activity Added и LastRemoval/Undo существуют только в памяти.
После reload бюджет восстанавливает обычный фильтр Catalog, остальные
фильтры пусты; Added без runtime-контекста не подтверждает старое добавление.

`usePlanPersistence` сохраняет только при изменении плана. Ошибки доступа
или квоты обрабатываются: приложение продолжает работать в памяти и явно
сообщает, что сохранение не удалось. Гарантированного offline-режима,
синхронизации между устройствами или вкладками не реализовано.

`app/planSession.ts` — чистые переходы состояния: add/remove/undo/filters.
Существующий `ActivityPlan` — единственная модель сохранения; session-state
не является отдельным persisted-планом. Только последняя запись удаления
хранит ID и исходную позицию. Повторное добавление удалённой группы снимает
соответствующий Undo; восстановление не создаёт дубликат.

Проверки: Vitest в `storage/__tests__`, `app/__tests__`, `pages/__tests__`
и прежние бизнес-тесты. В браузере проверены reload, все бюджеты, повреждение
JSON, гранулярное восстановление, сохранность legacy-ключей и отказ storage.
