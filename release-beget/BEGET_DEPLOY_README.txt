ДОЛГОЛЕТИЕ МАРШРУТ — ПУБЛИКАЦИЯ НА APACHE-ХОСТИНГЕ BEGET

Подготовлено: 27.10.2026.
Версия исходного проекта: d680da8be68f52faf62feb941f24ad046908da56 (main).
Архив: dolgoletie-marshrut-beget.zip.
Архив содержит новую production-сборку приложения, а не исходный код.
Сборка выполнена после успешного npm ci командой npm run build.

1. ПРОВЕРЬТЕ ВЫБРАННЫЙ САЙТ

В панели Beget выберите только сайт dolgoletie.initki.ru и посмотрите его
document root — папку, из которой Apache отдаёт файлы именно этого сайта.
Фактический путь берите из настроек сайта; не считайте общий каталог аккаунта
или папку другого домена подходящим местом для распаковки.

Не меняйте SSL-сертификаты, DNS, настройки доменов и другие сайты iNitki.
Если нужный сайт или его корневая папка ещё не настроены, остановитесь и
обратитесь к владельцу. Эта инструкция не разрешает создавать или менять
домены, сертификаты и настройки других сайтов.

2. СДЕЛАЙТЕ РЕЗЕРВНУЮ КОПИЮ

До замены файлов сохраните полную копию текущего document root этого сайта,
включая скрытый .htaccess и старые ресурсы. Храните резервную копию вне
публичной папки сайта. Это позволит восстановить прежнюю версию при проблемах.
Если в корневой папке уже есть чужие приложения или особые правила .htaccess,
не перезаписывайте их без проверки администратором.

3. РАСПАКУЙТЕ СБОРКУ

Распакуйте dolgoletie-marshrut-beget.zip в document root dolgoletie.initki.ru.
index.html должен находиться непосредственно в этой папке, а не внутри
дополнительной папки dist, app или release-beget.

Рядом должны быть папка assets, hero-photo.png, favicon.svg, icons.svg и
скрытый файл .htaccess. Включите показ скрытых файлов в файловом менеджере
или FTP-клиенте и убедитесь, что .htaccess действительно перенесён.
Не переименовывайте файлы в assets: их имена связаны с index.html.

Сам ZIP и эту инструкцию не нужно оставлять в публичной папке: загружайте
распакованное содержимое архива либо уберите ZIP после распаковки.
Не загружайте node_modules, .git, src, .env и файлы разработки.

4. НА СЕРВЕРЕ НЕ НУЖНО СОБИРАТЬ ПРОЕКТ

Это готовый статический сайт: npm, Node.js и PHP на Beget для его работы
не требуются. Не запускайте npm install или npm run build на хостинге.
Нужен Apache, обслуживающий статические файлы и разрешающий правила
mod_rewrite из .htaccess (AllowOverride для этих правил).

.htaccess обслуживает существующие файлы и каталоги напрямую. Другие пути
внутренне переписываются на /index.html, чтобы маршруты обработал React Router.
Это не внешний redirect: адрес в браузере должен сохраняться.
Правила предназначены для корня этого сайта, не для размещения в подпапке.
Если возникает HTTP 500 или прямые ссылки дают серверную 404, передайте
проверку mod_rewrite/AllowOverride администратору. Не меняйте SSL или DNS.

5. ПРОВЕРЬТЕ САЙТ ПОСЛЕ ПУБЛИКАЦИИ

Открывайте каждый адрес напрямую в новой вкладке, затем нажимайте F5:

  https://dolgoletie.initki.ru/
    Ожидается главная страница «Долголетие Маршрут».

  https://dolgoletie.initki.ru/activities
    Ожидается каталог занятий, работают поиск и фильтры.

  https://dolgoletie.initki.ru/my-plan
    Ожидается «Мой план», допускается пустое состояние.

  https://dolgoletie.initki.ru/activities/group-walk
    Ожидается карточка «Учебная группа: регулярная ходьба».

Все страницы после F5 должны открываться без серверной 404, белого экрана
и изменения адреса на /index.html. Проверьте фотографию на главной, стили
и загрузку ресурсов из assets. При наличии инструментов разработчика убедитесь,
что JS/CSS отдаются как файлы, а не как HTML-страница.

Проверьте также пользовательский сценарий: найти ходьбу в каталоге,
добавить в план, перейти в «Мой план», обновить страницу. Группа должна
сохраниться в этом же браузере. План хранится в localStorage браузера;
на другом устройстве или другом домене он автоматически не переносится.

Адреса выше — целевые адреса для проверки, а не подтверждение уже выполненной
публикации или работоспособности HTTPS. Если HTTPS не настроен или есть
предупреждение сертификата, сообщите владельцу и не меняйте сертификаты сами.

Каталог учебный, без реальной записи, авторизации, оплаты и серверной БД.
Межбраузерная, серверная и публичная приёмка ещё требуют отдельной фиксации.
При проблемах используйте резервную копию только этого сайта по согласованию
с владельцем; не затрагивайте другие сайты iNitki.
